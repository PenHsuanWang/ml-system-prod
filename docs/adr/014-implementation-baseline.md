# ADR-014: CPU implementation baseline and review resolutions

Date: 2026-10-29. Status: technical implementation decision under the user's request to start coding. This does not approve production SLOs, retention policy, runtime qualification or release.

The upstream source is the local `python-backend-server-template` checkout at commit `a0cea22a2a5d118b42a2955d3b58ef02c9d16be9`. Generic `server.py` defaults and the existing nine `src` layers are retained. ML composition is opt-in under `bootstrap/ml_*`; management does not import or instantiate Torch models.

1. Freeze an inference bundle before registration. Store the assigned Registry version in an external model binding. Evaluate the exact frozen bundle, then bind manual approval to its immutable evaluation/report. This resolves RV3-02 without weakening deployment approval.
2. Use an independent, monotonic routing revision as a fencing token. The reference local/VM ingress reads authoritative SQL routes. Activation and failure fencing use conditional updates; even a failure that keeps the same model increments the revision. Runtime cleanup follows fencing. External ingress adapters must implement equivalent semantics.
3. PostgreSQL is the application authority outside local development. SQLite is an explicit local/testing adapter, using the same transaction contracts; SQLite results are not PostgreSQL qualification evidence. Migrations run explicitly, never during API startup. Lock ordering is tenant/job before attempt.
4. Keep Taskiq/RabbitMQ, using manual acknowledgement. The relay uses a separate confirmed aio-pika publisher with mandatory returns. A worker ACK requires durable Job terminal evidence and a Redis transport snapshot. Redis is not the Job authority. Actual receiver qualification remains a required integration check.
5. `ml-json-v1` canonicalization uses NFC strings/keys, sorted keys, finite decimal JSON numbers without exponent notation, negative zero equal to zero, and rejects normalized duplicate keys/surrogates. Defaults are expanded by the versioned request DTO. It is an application-specific algorithm, not a claim to implement RFC 8785. Replay lookup precedes backend resolution.
6. The first fixture is a deterministic two-feature CPU MLP binary classifier. Train/validation/test indices are fixed at 384/64/64 samples; transform statistics use only training. Operators can explicitly import tenant-scoped immutable snapshots with the same feature/label contract and disjoint fixed splits. The content digest includes the split indices. This is an engineering fixture, not a production dataset or quality baseline. Resource limits and default 24-hour idempotency retention are local proposals; the reference serving pool reserves two process slots, including unconfirmed retirements.
7. The local filesystem tracker implements the Registry/Tracking port only in dev. Staging/production require explicit PostgreSQL, MLflow and pinned source/image configuration. An installed runtime is not automatically a qualified profile.

Remaining product gates are unchanged: representative data, numeric SLOs and windows, retention/audit periods, RPO/RTO, target infrastructure, production secrets and sign-off with environment evidence.
